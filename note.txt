pages/	What a screen shows
components/	Reusable pieces (buttons, cards, layouts)
api/	Talking to Laravel, nothing else
context/, hooks/	Shared state like the logged-in user
routes/ (frontend)	Who may open which screen
routes/ (Laravel)	Which URL goes to which controller
Controllers/	Receive the request, return the response
Requests/	Validate input
Services/	Business rules (tokens, refunds, status changes)
Models/	Database tables as PHP classes
Policies/	Who may act on a specific booking (only its client or jobseeker can cancel)
Resources/	What JSON goes out

## Step 1 — Deploy the React + Vite PWA

I recommend Cloudflare Pages for the frontend. It supports Vite builds, GitHub deployments, HTTPS, and free `pages.dev` URLs.&#x20;

1. Open [Cloudflare Dashboard](https://dash.cloudflare.com/?utm_source=chatgpt.com) and create an account.
2. Go to Workers & Pages → Create → Pages → Connect to Git (the exact labels may vary).
3. Select your React repository on GitHub.
4. Configure these build settings.

| Setting                | Value                                          |
| ---------------------- | ---------------------------------------------- |
| Production branch      | `main`                                         |
| Framework preset       | React (Vite)                                   |
| Build command          | `npm run build`                                |
| Build output directory | `dist`                                         |
| Root directory         | `./` if the frontend is at the repository root |

If React is inside a monorepo folder, set the root directory to that folder instead.

Before deploying, test the build locally:

```
npm install
npm run build
```

If it succeeds, deploy from Cloudflare. You'll receive a URL similar to `https://your-project.pages.dev`.

### Configure the API URL

In your React project, create or update `.env.production`:

```
VITE_API_URL=https://YOUR-BACKEND-URL/api
```

Use the real backend URL once Laravel is deployed. Your code can read it with:

```
const API_URL = import.meta.env.VITE_API_URL;
```

Do not place passwords, Neon credentials, or private API keys in variables starting with `VITE_` because those values are included in frontend code.

## Step 3 — Connect Laravel to Neon PostgreSQL

Keep Neon as your database provider. For safer testing, create a separate Neon branch or a separate testing database so you don't accidentally modify important data.

1. Open [Neon Console](https://console.neon.tech/?utm_source=chatgpt.com).
2. Select your project and open Branches.
3. Create a branch named `testing` if your plan and project settings support it.
4. Select the testing branch and click Connect.
5. Copy its PostgreSQL connection details.

Neon provides standard PostgreSQL connection strings; use the connection information from its dashboard rather than guessing credentials.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://github.com\&sz=32)

GitHub



Configure the Laravel backend's environment variables using the testing branch's details:

```
APP_ENV=production
APP_DEBUG=false
APP_URL=https://YOUR-BACKEND-URL

DB_CONNECTION=pgsql
DB_HOST=YOUR_NEON_HOST
DB_PORT=5432
DB_DATABASE=YOUR_DATABASE
DB_USERNAME=YOUR_USERNAME
DB_PASSWORD=YOUR_PASSWORD
```

Set `DB_SSLMODE=require` if your Laravel PostgreSQL configuration supports that variable, or configure the connection's `sslmode=require` option in `config/database.php`.

Important: These are server-side settings. Add them through the backend host's environment-variable settings, not through React or a public repository. Check your Laravel version's database configuration before assuming every environment variable is recognized.

After confirming the backend points to the testing database, run migrations using the host's console or deployment command:

```
php artisan migrate --force
```

Don't run this against your existing database branch until you have confirmed the target and protected any data you need.

## Step 4 — Connect React and Laravel

Once Laravel is deployed, update `VITE_API_URL` in Cloudflare Pages to use the real API URL and redeploy.

Next, configure Laravel CORS to allow your frontend domain.

For example, in `config/cors.php`, allow your actual deployed origin:

```
'allowed_origins' => [
    'https://YOUR-PROJECT.pages.dev',
],
```

Make sure the API paths and HTTP methods your application uses are allowed. If you're using Laravel Sanctum with cookie-based authentication, you'll also need to configure stateful domains, credentials, and secure cookies correctly.

Test these endpoints:

- `https://YOUR-BACKEND-URL/up` — if your Laravel version exposes the default health route.
- `https://YOUR-BACKEND-URL/api/...` — a real API endpoint from your application.

The health route checks whether Laravel boots successfully; it doesn't necessarily prove the database connection is working. Test a database-backed API endpoint too.
